Contract 001: Filter people by name, rank and duty title

This is what api-dev and ui-dev build against, in parallel. It has no schema change and no migration.

Endpoints

RequestStatus and body
GET /Person
?name= (case-insensitive contains)
&rank= (case-insensitive exact)
&dutyTitle= (case-insensitive exact)

200 {success, message, responseCode, people[]}. This shape is unchanged. The list may be empty and its order is unspecified.

400 ValidationProblemDetails.

500 with an empty body.

Filters combine with AND. An empty value means no filter. Rank and dutyTitle filters never match unassigned people.

GET /Person/{name}
URL-encoded, trimmed, exact match ignoring case

200 {..., person}, where person is non-null.

404 {success: false, message: "Person not found", responseCode: 404, person: null}.

400 ValidationProblemDetails.

500 with an empty body.

Validation for all four inputs: at most 100 characters, using letters, digits, space, hyphen, apostrophe and period only (^[\p{L}\p{M}0-9 .'-]+$). The path value must also be non-blank. The 400 body is the framework's {type, title, status: 400, errors: {name|rank|dutyTitle: [...]}, traceId} and never echoes the input.

Person fields: personId, name, currentRank, currentDutyTitle, careerStartDate, careerEndDate. These are unchanged. Unassigned people have "" for rank and title (not null) and null dates.

Case-insensitivity: ASCII letters only (SQLite). élena does not find Élena.

Breaking changes

  • breaking GET /Person/{name}: an unknown name returns 404. It used to return 200 with person: null. This was agreed in the task.
  • breaking GET /Person/{name}: the match is now case-insensitive and ignores surrounding whitespace. Invalid input returns 400.
  • breaking GET /Person: invalid name, rank or dutyTitle returns 400. These parameters used to be ignored.
  • breaking On both endpoints, a 500 has an empty body instead of a BaseResponse carrying the exception message.
  • side effect GET /AstronautDuty/{name} (out of scope) shares the lookup, so an unknown name there also returns 404 and the match is case-insensitive.
  • UI internal StargateApi.getPerson(name) now returns Observable<PersonAstronaut | null>, and a 404 emits null. It has no callers.
