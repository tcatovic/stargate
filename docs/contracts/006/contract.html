Contract 006: ASCII-only names, exact name filter, validated POST /Person

Revision 2: what changed from revision 1 (the user changed the scope)

  • New: ASCII-only name rule, for all four endpoints that use it. The NFC step, the invisible-character set, the combining-mark limit and the 800-character raw bound are removed. Only ASCII whitespace is trimmed, so a no-break space at an edge is 400. Files: openapi.yaml (NameRule), data.md, tests.md sections A and C1.
  • New: GET /Person?name= is exact, with no contains. Files: openapi.yaml, data.md, tests.md sections A and C2.
  • Location stays /Person?name=<encoded> (accepted). It now returns exactly the created person. The tests use ASCII names.
  • The look-alike question is moot. The empty 500 body is accepted.
  • No UI type changes. Two UI comments are corrected (types.ts header).

Breaking changes (all accepted by the user):

  • Non-ASCII names get 400 on GET /Person (filters), GET /Person/{name}, PUT /Person/{personId} and POST /Person. This includes previously valid names such as Émile, NFD input, and a no-break space at an edge. The validation message wording changes.
  • GET /Person?name= is now exact (case-insensitive, trimmed). A partial name returns an empty list. For example, ?name=elena no longer finds Elena Vasquez.
  • POST /Person changes in several ways:
    • Body: { "name": "..." } instead of a bare string (400 or 415).
    • Success: 201 (was 200), with a Location header.
    • Duplicate: 409 (was 500 or a duplicate row).
    • Invalid name: 400 (was stored).
    • New statuses: 415 and 413.
    • 500: empty body (it used to contain the exception message).

The name rule (one definition, used everywhere)

trim ASCII whitespace (tab, LF, VT, FF, CR, space)   -- nothing else is trimmed
then 1..100 characters, each one of:  A-Z a-z 0-9 space . ' -
pattern ^[A-Za-z0-9 .'-]+\z   (no IgnoreCase, no \d, no Unicode normalisation)
  • Uniqueness and lookups compare ignoring ASCII case (SQLite NOCASE). For ASCII names that is complete case-insensitivity.
  • GET filters and the GET route check the value as sent, so an edge tab or newline is 400 there. That is unchanged from today, and task 008 can unify it.
  • Seed names, ranks and titles are all valid.

Domain rules

  • Rule 1: names are ASCII and trimmed, there is a NOCASE pre-check, and the existing unique index IX_Person_Name is the guarantee (a lost race is 409). Lookup by name is exact.
  • Rule 2: create inserts only a Person. Tests compare the astronaut tables before and after.

Removed

  • From InputRules:
    • NFC normalisation
    • the 28 invisible code points
    • the combining-mark limit
    • MaxRawLength
  • From GetPeople: LIKE, ESCAPE and EscapeLike.
  • CreatePersonPreProcessor (dead code).
  • The POST try/catch that returned ex.Message.

The applied migration AddUniquePersonNameIndex is not touched.
