Contract 008: One GetPeople query object, GET /Person/{name} removed

Files: openapi.yaml · data.md · types.ts · tests.md

Breaking changes

BREAKING GET /Person/{name} is removed. Any GET or HEAD on /Person/{x} now gets 405 Method Not Allowed, header Allow: PUT, empty body. That path belongs to PUT /Person/{personId}, so routing answers "method not allowed", not 404. No handler runs and no person data is returned. Use GET /Person?name=<name>. An unknown person is 200 with people: [] (it was 404).

Pending your answer to plan Q1. The task asked for a 404. The 405 is what the framework does without changing PUT. If you choose the PUT route-constraint alternative instead, only the Q1 rows, this card and the openapi note change.

BREAKING (UI internal) StargateApi.getPerson and GetPersonByNameResult are removed. No component used them.

Not breaking

  • GET /Person parameters and response shapes are unchanged. The parameters are name, rank and dutyTitle, all optional, case-insensitive exact, combined with AND. The 200 response is { people[], success, message, responseCode }, with "" rank and title for unassigned people. The 400 response is ValidationProblemDetails keyed name/rank/dutyTitle, and the input is never echoed.
  • Trimming matches the writes. Surrounding ASCII whitespace (tab, LF, VT, FF, CR, space) is removed before validation. A leading or trailing control character, or padding beyond 100 characters, now returns 200 instead of 400. No input that was accepted before is now rejected.
  • Over-long values return 400 with exactly one message, the shared name-rule message (it was "The field x must be a string with a maximum length of 100.").
  • Binding (unchanged, now written down): parameter names are case-insensitive, a repeated parameter uses its first value, and unknown parameters are ignored. query and query.name are not aliases and never switch a filter off.
  • Swagger: /Person keeps maxLength and pattern and loses only minLength: 0. GET /AstronautDuty's name gains maxLength and pattern. /Person/{name} and GetPersonByNameResult are gone.

Domain rules

  • Rule 1: one exact, trimmed, case-insensitive lookup by name (GET /Person?name=), backed by the unique NOCASE index.
  • Rule 2: SQL is unchanged. Unassigned people are matched by name alone and never by rank or dutyTitle.

Security note

When the object is bound with a plain [FromQuery] GetPeople query, ?query=x&name=%25 returns 200 with every person: validation and filters are skipped (observed in planning). The contract requires Name = "" on the action parameter, and tests Q5a-Q5f lock that in.
