Observations (not failures against the criteria)

  1. Doc gap on a truly fresh clone: no restore step. Repro: fresh git archive copy (no obj folder), cd exercise1/api; dotnet ef database update. Observed: error NETSDK1004: Assets file '.../obj/project.assets.json' not found. Run a NuGet package restore and "Unable to retrieve project metadata", exit shown as an error, no db created. Running dotnet restore (or dotnet build) first fixes it. The README's Create command therefore does not work literally on a never-built clone. Suggest adding dotnet restore (or dotnet build) to the procedure. In the real working tree obj already existed, so this is only visible from a clean checkout.
  2. Troubleshooting row is only partly true. README says an absolute-path problem produces "Database directory '...' does not exist". That check only runs for relative paths. An absolute override to a missing directory (Release, Data Source=/nonexistent/x.db) starts the app and fails on first request: HTTP 500 "SQLite Error 14: 'unable to open database file'". No acceptance criterion covers this.
  3. NULL-guard message is buried. dotnet ef database update prints a full .NET stack trace (about 20 lines) before the final "SQLite Error 19: 'MakeCareerStartDateRequired: ...'" line. The message is clear and last, so it is usable; dotnet ef shows stack traces unless run with default verbosity changes. Cosmetic.
  4. Also seen: dotnet ef database update logs every SQL command at info level (very noisy). Un-migrated or 0-byte DB makes GET /Person return HTTP 500 "no such table: Person", as the README troubleshooting row describes.
